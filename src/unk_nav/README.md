# unk_nav

未知环境下的**局部反应式导航**核心算法。零第三方依赖，只用 C++14 标准库，可交叉编译到华为 MDC。

与同工作区的 `rlp_*`（沿路规划）**完全独立**，不复用任何代码，也不引入道路/走廊/边界概念。
成熟后按文末「融入路径」并入。

---

## 一、核心约束

模块的形态由四条约束决定，任何改动都不得破坏：

1. 规划器**只能看到车周有限范围的局部占据栅格**（车体系 `base_link`）；
2. 终点在局部窗口**之外**，距离远大于窗口尺寸；
3. 因此**不存在全局地图，也不做全局搜索**。每周期把远处终点沿方向投影进窗口内得到一个
   **子目标**，在局部栅格上滚动规划（滚动时域）。`astar::plan()` 的 `goal` 参数必须是这个
   窗口内子目标，传入真实终点属于误用，会被越界检查直接拒绝；
4. 环境未知，栅格中有 `unknown` 区，采取**乐观策略**：`unknown` 可通行但代价略高。

还有一条容易忽略但很关键的区分：**「越界」（窗口之外）绝不可通行，「unknown」乐观放行**。
两者混为一谈，搜索会跑出栅格边界。

### 主要矛盾与当前能力边界

只有局部栅格 + 远处终点 ⇒ **凹形障碍造成的局部极小**是主要矛盾：
子目标投影落在凹槽里，A\* 把它吸附到凹槽内壁，车开进去就出不来。

分界线是**凹槽深度与前瞻距离（`lookahead_ratio × sensor_range`，默认 4.2 m）的关系**：

| 场景 | 表现 |
|---|---|
| 无障碍 / 凸障碍（横墙、柱子） | ✅ 滚动时域 + 局部 A\* 自行绕开 |
| 凹槽深度 **<** 前瞻 | ✅ A\* 能看到臂端，绕出去（实测绕行比 1.05） |
| 凹槽深度 **>** 前瞻 | ❌ 局部极小 → 无进展判定触发 → RECOVERY → **ABORT** |

复现（凹槽深 6.3 m > 前瞻 4.2 m）：

```bash
./unk_nav_demo --goal 20 0 --obs 10 -1.2 10.3 1.2 \
                          --obs 4 -1.3 10.3 -1.0 \
                          --obs 4  1.0 10.3  1.3
```

**解决凹障碍需要 Bug 式沿轮廓绕行（`BOUNDARY_FOLLOW`）+ 子目标扇形候选展开，
这两项已明确排除在本模块范围外**（决策见文末）。当前行为是主动 ABORT 并把决定权
交回上层，不尝试自己爬出来。

## 二、模块与数据流

```
NavInput{ local_grid(base_link), vehicle_pose(全局), goal(全局), current_speed, now }
   │
   ├─ 1. geom::globalToBase        终点 → 车体系
   ├─ 2. grid::inflate             障碍按 inflation_radius 膨胀
   │    grid::clearFootprint       车体足迹强制清空（顺序不可颠倒）
   ├─ 3. subgoal::project          远处终点 → 窗口内子目标（射线-包围盒，方向不掰偏）
   ├─ 4. astar::plan               8-连通搜索 → LOS 拉直 → 平滑 → 按段加密采样
   ├─ 5. speed::limit              制动包络硬校验 + 四条限速取最小
   └─ 6. fsm::BehaviorFsm          IDLE/GO/RECOVERY/ARRIVED/ABORT
   │
NavResult{ path(base_link), recommended_speed, state, emergency_stop, subgoal, reason }
```

| 文件 | 职责 |
|---|---|
| `types.h` | `GridMap`（`blockedAt`/`feasibleAt`）、`Path`（带弧长与曲率）、`NavParams`、`NavInput`/`NavResult`、`NavState`、`kPi`/`kSqrt2` |
| `geom_util` | 纯几何，不接触栅格：角度归一化、全局↔车体系变换、弧长、两种重采样、裁剪、点线距、三点曲率、`toPath` |
| `grid_util` | 只接触栅格：圆盘膨胀核、膨胀、足迹清空、线段/折线通行检查、LOS 拉直、螺旋找可行格 |
| `astar` | 局部栅格 A\* + 可复用 `Workspace` + 后处理编排 |
| `path_smooth` | 拐点圆弧倒角 + 拉普拉斯松弛，每步碰撞复验 |
| `subgoal` | 远处终点 → 窗口内子目标投影 |
| `speed_planner` | 沿线稠密采样障碍距离、制动包络、四条限速 |
| `behavior_fsm` | 行为状态机，**全部跨周期记忆都在这里** |
| `nav_core` | 门面：外部只需认识 `NavCore` + `NavInput` + `NavResult` |

## 五、路径平滑

### 为什么必须做

A\* 出的是栅格阶梯，LOS 拉直后剩尖角折线。直接交给速度规划会有两个后果：拐点曲率极高，
`w = v·κ ≤ w_max` 把速度压死；曲率从 0 阶跃到峰值，`dk/dt ≤ dk_max` 再压一次。

实测横墙绕行（平滑前 → 平滑后）：

| | 平滑前 | 平滑后 |
|---|---|---|
| 最大曲率 | 32.49 /m（转弯半径 3 cm） | **8.11 /m** |
| 过弯最低速 | 0.038 m/s = **17% v_max** | 0.220 m/s = **100% v_max** |

车原本是爬过拐角的，平滑后满速通过。

### 三步做法

1. **拐点圆弧倒角**（`smooth::filletCorners`）
   对每个内角插入与两边相切的圆弧，把曲率上界压到 `1/r`。半径由**目标过弯速度**反解，
   同时满足两条约束：
   ```
   r = max(v_corner / w_max,  v_corner² / a_lat_max)
   ```
   低速差速车由角速度约束决定（0.22/2.84 = 0.0775 m），30 km/h 实车由横向加速度决定
   （8.3²/2.5 = 27.6 m）。换车型只需给出想要的过弯速度，不必手算半径。
   圆弧采样点若碰撞则**半径折半重试**，重试耗尽就保留尖角 —— 宁尖勿撞。

2. **拉普拉斯松弛**（`smooth::laplacian`）
   只做倒角的话，曲率从 0 跳到 `1/r` 仍是阶跃，`dk/dt` 约束照样限速。松弛把阶跃摊开。
   端点固定（起点是车位、终点是子目标，都不许挪），每轮迭代后碰撞复验，撞了就停在上一轮。

3. **最终复验**（`smooth::run`）
   输出前整体再查一次 `polylineFree`，任何意外都退回输入。**宁可交出尖角路径，
   绝不交出撞障路径。**

平滑插在 **LOS 拉直之后、加密采样之前** —— 此时拐点还是显式顶点，倒角才识别得出来。

### 曲率必须按弧长基线测量

这是本轮挖出的最重要的一个缺陷。原来 `toPath` 用**相邻两点**算三点外接圆曲率，于是曲率
随采样密度变化：点距 0.05 m 时 `κ ≈ 565 × 横向偏差`，栅格阶梯的任何微小抖动都被放大成
30+/m 的假曲率。同一条几何路径按 0.02 m 重采样，报出的曲率是 0.05 m 的 2.5 倍 ——
仿真与实车 `path_spacing` 不同时这是致命的。

改为按 `curvature_baseline`（默认 0.30 m，约车辆 0.2~0.5 s 走过的距离）取弧长相距
±baseline/2 的两点来估：

| 输入 | 相邻点估 | 基线估 |
|---|---|---|
| 带 ±0.01 m 抖动的直线 | 13.79 /m（假曲率） | **1.75 /m** |
| R=2 m 真圆弧，spacing 0.05 | 0.50 | 0.50 |
| R=2 m 真圆弧，spacing 0.02 | 0.50 | 0.50（**与密度解耦**） |

端点附近放不下完整基线时，**不能把基线夹成不对称**（一边很短一边很长）：三点外接圆公式
分母是 `ab·bc·ca`，短边会把曲率严重放大，端点处凭空冒出假尖峰（实测 4.91 /m）。
正确做法是只在能放下完整基线的内点区间计算，区间外沿用边界值。

## 六、性能与 10 Hz

`NavCore::plan()` 单周期耗时（AMD Ryzen 9 7940HX / x86_64，Release，不含感知与控制替身）：

| 尺度 | 栅格 | 平均 | p95 | p99 | 最差 | 10Hz 预算占用 |
|---|---|---|---|---|---|---|
| 仿真：雷达 12 m，空世界 | 16.6 万格 | 0.131 ms | 0.166 ms | 0.177 ms | 0.98 ms | 最差 10% |
| 仿真：雷达 12 m，横墙绕行 | 16.6 万格 | 0.635 ms | 2.52 ms | 2.78 ms | 2.89 ms | 最差 29% |
| **实车：雷达 30 m，空世界** | **104 万格** | **1.217 ms** | 1.49 ms | 1.52 ms | **6.53 ms** | **最差 65%** |
| 实车：雷达 30 m，带障碍 | 104 万格 | 0.875 ms | 1.15 ms | 1.20 ms | 7.51 ms | 最差 75% |

**结论：10 Hz 没问题。** 最坏单周期 7.5 ms，占 100 ms 预算的 75%；平均只占 1%~12%。
MDC 是 ARM，按 3~5× 折算，平均约 3~6 ms、最坏约 22~38 ms，仍在预算内。
最差值出现在窗口刚被大量新障碍填满的那一两个周期（A\* 扩展格数骤增），是尖峰不是常态。

两项为此做的设计：

- **每周期零堆分配**：`astar::Workspace` 跨周期复用，用**代际标记**（`stamp[i] != gen`
  即视为未访问）代替每次把 `g_cost` 整体填 inf。于是成本只与**实际扩展的格数**相关，
  与栅格总格数无关。不做这件事，104 万格窗口就是每周期 12 MB 的分配 + memset，
  10 Hz 下 120 MB/s 的内存 churn，还会带来分配器抖动。
- 剩余唯一随栅格尺寸线性增长的开销是 `grid::inflate` 的整图拷贝与扫描（104 万格约 1 MB）。
  目前可接受；若将来吃紧，可只对车周感兴趣区域膨胀。

## 七、关键参数

`NavParams` 全字段见 `types.h`，这里只说需要理解的几条。

### 无量纲化原则

所有与**感知尺度**相关的距离都表达为 `sensor_range` 的比例：

```
局部窗口  = 1.7  × sensor_range     (仿真 20.4 m ← 12 m；实车 51 m ← 30 m)
前瞻距离  = 0.35 × sensor_range     (lookahead_ratio)
子目标区间 = 0.10~0.20 × sensor_range (subgoal_min_ratio / subgoal_max_ratio)
```

换车型 / 换雷达只改 `sensor_range` 一个值，整定结果按比例自动迁移。

**但动力学参数不参与这个缩放**：`inflation_radius`、`smooth_corner_speed`、`a_decel_max`、
`a_lat_max`、`w_max` 由车辆本身决定，换雷达不该改变过弯半径。

### 以米为单位、不以格数为单位

`goal_snap_dist`（子目标吸附半径）给的是米，`nav_core` 内部才按当前分辨率换算成格数。
若直接给格数，`resolution` 从 0.05 改到 0.10 时吸附范围会悄悄翻倍。

### 膨胀半径是留给控制器的余量

`inflation_radius = robot_radius + 余量`。这个余量是给**下游控制器跟踪误差**留的，不是
随便给的小数：路径在膨胀栅格上搜出，只保证中心线有 `(inflation_radius - robot_radius)`
的净空。若控制器跟踪误差（尤其纯跟踪在拐点切内角的弦差）超过净空，车会开进膨胀层被
自己的安全边距困死（见「踩过的坑」第 5 条）。要么控制器保证误差不超过净空，要么调大这里。

## 八、踩过的坑（都有回归测试）

| # | 坑 | 现象 | 修法 | 回归测试 |
|---|---|---|---|---|
| 1 | **膨胀吃掉车自己** | A\* 起点即障碍，永久死锁 | 膨胀后必须调 `clearFootprint()` | `astar` 第 11 组 |
| 2 | **加密采样切拐角** | 路径重新穿进障碍，U 形墙臂端必现 | `resampleByArc` 按全局弧长打点，相邻点跨过拐点时连线切掉拐角内侧。改用 `resampleKeepCorners` 按段细分并强制保留拐点 | `geom_util` 对照组 + `astar` 第 4 组 |
| 3 | **8-连通穿墙角** | 车擦过对角障碍的角 | 对角移动要求两侧正交格均可行，默认 `forbid_corner_cutting=true` | `astar` 第 9 组对角墙 |
| 4 | **末段死区** | 车停在离终点 0.59 m 处放弃 | 子目标投影设了「推进距离下限 0.6 m」，与到达容差 0.15 m 之间形成死区：既不判到达又不出子目标 → 连续失败 → 误触发脱困到 ABORT。只有**被窗口截断**才算投影失败，终点本身就近时必须照常输出 | `subgoal` 末段收敛 + `nav_core` ARRIVED |
| 5 | **控制器切内角吃掉安全边距** | 车开进膨胀层被自己困死，ABORT | 纯跟踪的「车→预瞄点」弦会切进拐角内侧，速度越高 `ld` 越大切得越深。demo 控制器改为从 `ld` 处往近处收缩、取第一个弦无碰撞的点。**实车控制模块必须遵守同一契约** | demo 横墙场景（修前 FAIL、修后 PASS） |
| 6 | **曲率按相邻点估计** | 过弯速度被压到 17% v_max | 见「曲率必须按弧长基线测量」 | `曲率测量基线` 组 |
| 7 | **基线在端点被夹成不对称** | 端点处冒出 4.91 /m 假曲率尖峰 | 只在能放下完整基线的内点区间计算，区间外沿用边界值 | 同上 |
| 8 | **平滑后障碍位置放错** | 单测误报 | 测倒角回退时，障碍块压在了原路径所在的格子上，输入折线本身就是撞的。障碍必须严格落在拐角内侧、不碰两条原线段 | `path_smooth` 贴障拐角 |

## 九、几个设计判断（记下来防止被改回去）

- **`kappa_max` 默认 0（关闭硬门限）**。差速底盘能原地转向，曲率本身不构成运动学约束；
  栅格直角拐点曲率约 `√2/resolution ≈ 28`，用固定门限硬卡会把所有正常拐弯判死
  （实测：绕行路径已搜到，却被 `kappa_exceeded` 急停至 ABORT）。真正该卡的是
  `w = v·κ ≤ w_max` 与 `a_lat = v²κ ≤ a_lat_max`，这两条是软限速，已实现。
  阿克曼底盘才需要打开 `kappa_max`。
- **障碍距离必须沿线稠密采样**。只在路径顶点查，顶点稀疏时会整段跨过薄障碍，把 `d_obs`
  误判成 inf，制动包络随之失效。
- **`unknown` 乐观放行**。这是「未知环境探索」的正确语义：敢往没探过的地方开，探出障碍
  再滚动重规划。`unknown_cost` 是探索偏好旋钮，>1 偏向已知区。
- **到达判定只判距离、不判航向**。差速底盘原地转向能力充足，强制对齐航向会让车在终点
  附近来回转圈。需要定向停靠时再加参数与判定逻辑，不要留一个"设了但不生效"的旋钮。
- **接口里不留死状态与死参数**。`NavState` 的每个值都真实产生，`NavParams` 的每个字段
  都真实被读取。集成方按枚举写 switch 时不会遇到永不出现的分支，调参时不会拧到空旋钮。
- **平滑的每一步都做碰撞复验，失败即回退**。平滑是「锦上添花」，绝不能为了光滑牺牲安全。

### 已明确排除在范围外（决策记录，不要再当 TODO 提）

- **凹形障碍绕行（Bug 式 `BOUNDARY_FOLLOW`）** 与 **`RECOVERY` 实际脱困运动**：
  用户决定暂不考虑。相应地，代码里不留任何"预留但不生效"的接口 ——
  已删除 `NavState::BOUNDARY_FOLLOW` 枚举值、`fan_bearings` / `fan_half_deg` /
  `leave_point_tol` / `block_dist` 四个死参数，以及 `yaw_tolerance`（从未被到达判定读取，
  但文档声称"可开启"）。接口里出现的每一个状态和参数都是真实生效的。

### 待办（按优先级）

1. **实车尺度 + 障碍绕行会 ABORT**
   `--range 30 --goal 200 40 --obs 20 -6 21 6` 复现。原因是 `goal_snap_dist = 0.5 m`
   无法从 1.32 m 厚的膨胀墙里把子目标吸附出来。修法有两条：调大 `goal_snap_dist`
   （最简单，先试这个），或做子目标扇形候选展开（已排除范围）。
2. **换终点 / 换周期时的路径一致性**
   现在每周期独立重规划，可能产生跳变。可加与上一帧路径的偏差惩罚。
3. **`inflate` 的感兴趣区域化**
   实车尺度下它是唯一随栅格总格数线性增长的开销（104 万格约 1 MB 拷贝 + 扫描），
   目前占比可接受。
4. **ROS 节点壳 + Gazebo 仿真**
   两者都不进 MDC 交付物，等有实车接口定义后再做。

### 已知的行为特性（不是 bug，但集成方必须知道）

- **无进展判定用"朝终点推进量"而非"位移量"**（`behavior_fsm.cpp` 有完整论证）。
  位移量判定有致命盲区：车在凹槽里横向振荡时位移不小，判定永远沉默，模块会持续
  上报 `GO` + 满速。实测深凹槽场景旧实现振荡 280 秒全程报 GO —— 不是报错，是谎报
  健康。改成推进量棘轮后如实 ABORT。代价：`stuck_dist` 必须小于绕行期间每
  `stuck_time` 的正常推进量，否则必要的绕行会被误判（默认 0.05 m / 3 s，而
  `v_max × stuck_time = 0.66 m`，余量充足）。
- **`RECOVERY` 不产生任何运动**，只是上报一个状态；连续 3 次即 `ABORT`。
  上层收到 `ABORT` 需要自己决策（换终点 / 人工接管 / 停车）。
